# Пайплайн спрайтов и вариантов

Как заменить/дополнить графику генератора карт, не трогая код генерации.

## 1. Главное правило

Данные карты (тайлы, деревья, камни, постройки) **не меняются** — их проверяют
тесты (`scripts/layout-test.ts` сравнивает результаты через `deepEqual`).
Вся вариативность живёт в слое отрисовки:

| Слой | Что делает | Файл |
| --- | --- | --- |
| `assets.ts` | находит файлы-варианты `name`, `name-2`, `name-3`… | `src/lib/assets.ts` |
| `spriteLook.ts` | для каждого объекта детерминированно выбирает вариант, оттенок, отражение и масштаб | `src/lib/spriteLook.ts` |
| `decor.ts` | рисует мелкий декор (трава, цветы, камешки, мох, трещины) | `src/lib/decor.ts` |

Всё считается из координат объекта и «соли», поэтому результат стабилен между
перерисовками и не требует хранения доп. полей в сохранении.

## 2. Имена файлов

Файлы лежат в `src/assets/cartography/` и подхватываются автоматически
(`import.meta.glob`).

- **Базовое имя** — как в коде: `oak`, `pine`, `rock`, `smallRock`, `wall-straight`,
  `marketStallMeat`, `crypt-altar`, `furniture-bed`, `decor-tuft`…
- **Варианты** — суффикс `-2`, `-3`, `-4`: `oak-2.webp`, `oak-3.webp`.
  Первый вариант — файл без суффикса. Сколько файлов — столько вариантов,
  распределение равномерное по хэшу.
- **Декор** (новые имена, пока нет картинок — рисуется вектором):
  `decor-tuft`, `decor-flower`, `decor-leaf`, `decor-pebble`, `decor-twig`,
  `decor-moss`, `decor-crack`, `decor-snow`, `decor-litter`, `decor-shroom`.

Имя с суффиксом варианта не должно конфликтовать с настоящими именами: `wall-straightShort`
не является вариантом `wall-straight` — вариант только числовой суффикс.

## 3. Нарезка листов

`scripts/slice-sheet.py` режет сгенерированный лист на WebP-спрайты с прозрачным
фоном. Требуется numpy и Pillow (есть в bundled-питоне DSH).

```bash
# 2×2: деревья
python scripts/slice-sheet.py assets/source/tree.jpg -o src/assets/cartography \
    --mode quad --names oak,oakGold,pine,bush

# 4×4 по сетке: городские пропсы
python scripts/slice-sheet.py assets/source/city.jpg -o src/assets/cartography \
    --mode grid --rows 4 --cols 4 --names wagon,wagonCovered,wheelbarrow,wheelbarrowStone,...

# авто: ищет предметы на белом фоне по связным областям
python scripts/slice-sheet.py assets/source/dungeon_decor.jpg -o /tmp/decor \
    --mode auto --prefix crypt- --min-area 0.0004

# 2×2 текстуры (бесшовные)
python scripts/slice-sheet.py assets/source/grass.jpg -o src/assets/cartography \
    --mode quad --names grass,meadow,darkGrass,dirt
```

Полезные флаги:

- `--white 246` — порог «белого фона» (понизить, если фон сероватый);
- `--pad 6` — отступ вокруг спрайта;
- `--min-area 0.0004` — доля площади листа, ниже которой область считается мусором;
- `--lossy` — WebP с потерями (мельче, но тонкие линии хуже);
- `--force` — перезаписывать файлы вместо авто-суффикса `-2`, `-3`.

Скрипт пишет `_manifest-<имя>.json` со списком полученных файлов и размерами.

## 4. Соглашение по листам

- **Объекты** (деревья, камни, мебель, постройки, ловушки): чистый белый фон,
  вид строго сверху, без теней и рамок, по центру ячейки, 1–2 px тёмный контур.
- **Текстуры**: лист 2×2 из четырёх бесшовных квадратов; при тайлинге швы не видны.
  Текстуры кладутся группами (4 разных материала на лист).
- **Варианты**: 3–5 листов одной категории лучше, чем один лист с 16 разными
  предметами — повторяемость силуэтов убивает «уникальность» сильнее, чем набор.

## 5. Как проверить

```bash
node node_modules/typescript/bin/tsc --noEmit     # типы
npm run build                                     # сборка (обязателен TMP-редирект)
node scripts/layout-test.ts                       # генерация не изменилась
```

Сборка на этой машине требует перенаправить TMP, иначе esbuild падает с
`Access is denied`:

```powershell
$tmp = "C:\AbsoluteDND\cartographer\.tmp"
New-Item -ItemType Directory -Force -Path $tmp | Out-Null
$env:TMP = $tmp; $env:TEMP = $tmp
npm run build
```

Затем `dist/index.html` копируется в `C:\AbsoluteDND\v2.2.1\templates\generator.html`
(см. `MERGE_PROMPT.md`).

## Чистка краёв и белых просветов

После нарезки листов полезно прогнать два скрипта:

- `python scripts/clean-sprite-edges.py` — для **всех** спрайтов: снимает примесь белого
  у полупрозрачных пикселей, убирает мелкие светлые точки в кольце у прозрачности и
  подрезает внешний слой силуэта на 1 px. Крупные светлые детали (мрамор, кость, ткань)
  не затрагиваются. Ключи: `--only name,name`, `--dry-run`, `--quality`.
- `python scripts/fix-fringe.py` — точечно для листвы: дополнительно гасит нарисованную
  светлую обводку (`remove_white_ridges`, `remove_boundary_white`).

Белые просветы внутри кроны (щели между ветвями) убирает `punch_white_holes` в
`scripts/reslice-sprites.py`: связное пятно почти белого меньше 5 % площади спрайта
становится прозрачным. Для декора/грибов правило отключено, чтобы не выбить белые
лепестки и шляпки.
