
```powershell
node node_modules\typescript\bin\tsc --noEmit
```

```powershell
$tmp = Join-Path (Get-Location) '.tmp-build'

$env:TEMP = $tmp
$env:TMP = $tmp
```

## 3. Ловушки среды (Windows/PowerShell; проверено на рабочей машине)

| Симптом | Причина | Решение |
|---|---|---|
| `npm` не запускается, «выполнение сценариев отключено» | PowerShell 5.1 блокирует `npm.ps1` | использовать `npm.cmd` |
| `spawn EPERM` при `vite`/`npm run dev` | esbuild поднимает дочерний процесс через pipe-каналы; sandbox их блокирует | запускать с полным доступом (`danger-full-access` или эквивалент) |
| `EBUSY: ... .tmpdir\...` и падение Vite | редакторы/агенты пишут файлы через sidecar-каталоги `*.tmpdir`, chokidar пытается их наблюдать | уже исправлено в `vite.config.ts`: `server.watch.ignored` для `**/*.tmpdir/**`, `**/*.tmp`, `node_modules`, `.git`. Не удалять |
| `build` падает: `Access is denied` при удалении `%TEMP%\esbuild-*` | esbuild не может удалить свой временный файл в системном TEMP | перед сборкой задать `TEMP`/`TMP` внутри проекта: см. §1 |
| `pwsh` не найден | в системе Windows PowerShell 5.1, не PowerShell 7 | использовать `powershell.exe`; для `.ps1` — `powershell.exe -NoProfile -ExecutionPolicy Bypass -File script.ps1` |
| Кириллица в inline-командах PowerShell ломается | кодировка консоли/аргументов | хранить русский текст в `.ps1` с BOM или в файлах, не в командах |
| Переменные `$w` и `$W` конфликтуют | PowerShell не различает регистр | не использовать имена, различающиеся только регистром (временные скрипты уже на этом спотыкались) |
| `scripts/*.ts` не запускаются напрямую | импорты без расширений, `tsx` не установлен | `npm i -D tsx` или временная копия с `.ts` в импортах (Node 24 умеет strip types) |
| Браузерные тесты не запускаются | нет `playwright` | `npm install --no-save playwright`, `npx playwright install chromium`, затем dev-сервер и `node scripts/*.cjs` |

Полезно знать:

- Node **v24.21.0**, npm **12.2.0**, Git **2.56**, Vite **7.3.7**, React **19.2.6**, TypeScript **5.9.3**.
- В рабочей области уже был инцидент: Vite падал от временных каталогов редактора. Игнор в конфиге стабилен, проверен правками.
- `gh auth setup-git` требует git в PATH у процесса gh; при необходимости сначала расширьте PATH.

## 5. Модель данных

`GenSettings` (см. `src/lib/types.ts`):

- `seed`, `biome` (9: forest/plains/swamp/desert/snow/cave/dungeon/village/town)
- `width` 10–100, `height` 10–80, `roughness`, `waterLevel` (0–0.7), `vegetation`, `rocks`, `structures` (0–6), `ruined`, `river`, `road`, `caveOpenness`, `rooms` (2–14), `settlement`, `density`, `publicSpaces`
- `cryptDetail` (0–1), `cryptTraps`, `cryptChasms`, **`cryptArchetype`** (`tomb | catacombs | temple | archive | prison`, по умолчанию `tomb`)
- **`sceneArchetype?`** — `'auto'` (прежняя генерация) или id сцены из `src/lib/gen/archetypes.ts`; действует только для открытых биомов в структурном движке. Отчёт сцены лежит в `map.plan.archetype` и в проект не сохраняется.

- **`dungeonLayout?`** (`'classic' | 'varied'`), **`dungeonLevels?`** (1–4), **`dungeonLevel?`** (0–3). `varied` запускает `gen/dungeonArchitect.ts`; без поля склеп строится прежним путём. Отчёт пишется в `map.plan.dungeon`.
- **`settlementType?`** (`'classic'` или id из `gen/settlementTypes.ts`), **`settlementLayout?`** (id планировки). Тип запускает `gen/settlementPlanner.ts`; без поля или с `'classic'` используется старый `buildPlan`, и golden-хэши не меняются. Отчёт и геометрия стен пишутся в `map.plan.settlement`.

`MapData`: `width`, `height`, `biome`, `cells: Cell[][]`, `trees`, `rocks`, `structures`, `buildings?`, `civic?`, `crypt?`, `cryptRooms?`, `furnitureSprites?`, `chests`, `river`, `road`, **`doors?`** (`{ x, y, kind }`, только на клетках `door`; `'normal'` не хранится; `pruneDoors` удаляет метки, чья клетка перестала быть дверью). `EditorSettings.doorKind?` задаёт вид двери для кисти.

`Cell`: `terrain` (22 значения), `height`, `moisture`.

`CryptObject`: `kind`, `x/y/w/h`, `rotation`, `variant`, `source: 'layout'|'manual'`, `hidden?` (тайные ловушки). `CryptRoom`: прямоугольник + `theme` (8 тем).

`Project` (`project.ts`): `version: 1`, `gen`, `render`, `map: MapData | null`, `editor?`.

- `map: null` означает «правок не было, восстанови карту из seed». После правки хранится полный снимок.
- localStorage: ключ `battlemap-studio-project-v1`; импорт JSON ≤ 8 МБ; до 16 пользовательских спрайтов по ≤ 240 000 символов base64.
- Валидация строгая по диапазонам и лимитам, но старые проекты без новых полей получают дефолты (`cryptArchetype: 'tomb'`, `showRoofs` и т. п.).

## 6. Как генерируется склеп

1. **План залов** — `cryptBlueprint` (архетип; `cryptRoomCapacity` = `floor((width-3)/5) * floor((height-3)/5)`, затем `min(rooms, capacity)`), с гарантией числа через `finishLayout`/`packBlueprint`.
2. **Вырубка** — `generateDungeon`: прямоугольные комнаты, MST-коридоры (ближайший + петля), стены в одну клетку с удалением внутреннего слоя.
3. **Двери** — эвристика 85% + гарантирующий проход: у каждого зала появляется дверь на периметре (кроме одночного зала).
4. **Вода** — лужи по низким клеткам зала (отступ от стен, не коридор, не у двери), вода проходима (`open` включает `water`).
5. **Декор** — `decorateCrypt`:
   - BFS-глубина от входа, темы: `entry` снизу, главный зал — по архетипу (`CRYPT_HALL_THEME`), остальные — по `ARCHETYPE_THEMES`;
   - зарезервированные проходы (BFS-«осевые» клетки) и запрет блокировки дверей;
   - опасности только в `sanctum/burial/ossuary/storage`;
   - базовый набор (`BASE`) + свет (`LIGHT`), сцены (`SCENES`, 2 на тему), настенные украшения (`WALL_ORNAMENTS`);
   - бюджет мебели `round(площадь × (0.028 + 0.155 × detail))`, слот-ориентированный RNG;
   - ловушки только в коридорах, с приоритетом 2–3 клеток перед дверью.
6. **Рендер** — `renderMap` рисует рельеф, стены, двери, дома, объекты, свет, сетку. Стены — `wallPaint.ts`: каменная лента по контуру пола с круглыми стыками, без отдельных квадратных блоков; сетка не пересекает стены.

### Архетипы

| id | Планировка | Главный зал |
|---|---|---|
| `tomb` | BSP + центральный зал | `sanctum` |
| `catacombs` | колонны небольших камер 4–7 × 4–6 | `sanctum` |
| `temple` | зал до 18×13 + приделы | `sanctum` |
| `archive` | два ряда длинных залов 9–15 × 4–5 | `archive` |
| `prison` | камеры 4×4 + пост 8×7 | `watch` |

### Детерминизм и монотонность (важно не сломать)

- Только `mulberry32`/`hash2`/`mixSeed`; `Math.random` в генерации нет.
- Сид раскладки зависит от зала и слота (`rngFor(seed, room.x, room.y, salt)`), а не от длины `map.crypt`; поэтому рост детализации **добавляет** предметы, не двигая уже поставленные.
- Тест `crypt-test.ts` проверяет `detail 0.4 ⊆ 0.7`; сохраняйте это свойство.
- Изменение алгоритма меняет карты у проектов с `map: null`; сохранённые карты не меняются. Версии генератора пока нет.

## 7. Что сделано

### P0 — гарантии и базовое качество
- Число залов = `min(запрошено, вместимость)`, запасная сетка; панель показывает «Залы N из M».
- Дверь у каждого зала; одночный зал без двери.
- Темы по глубине; главный зал по размеру/глубине.
- Опасности только в подходящих залах.
- Детализация монотонна (слот-сиды, скелет до мебели).
- Базовый набор и свет в каждом зале (в т. ч. при detail 0).
- Ловушки только в коридорах, не на проходе.
- Тесты расширены; UI-подсказки.

### P1 — сцены и читаемость
- Сцены на каждую тему (алтарь со свечами и кругом, саркофаги, стеллажи, витрины, клетки, ящики).
- `wallFace`: 9 видов (знамя, гобелен, зеркало, маска, занавес, святилище, колокол, каменный глаз, храмовые маски) — только на стенах; `canPlaceCrypt`/`pruneCrypt` учитывают.
- Второй источник света в больших залах; ловушки перед дверьми.
- Лужи по низким местам, вода проходима.
- README и `docs/crypt/` обновлены.
- Из спрайт-листа добавлены 26 природных объектов (валуны, осыпи, сталагмиты, лужи, колодец, мох, кустарник, плющ, корни, лишайник, трещины, гнёзда, кости, брёвна, кристаллы); белый фон удалён, WebP прозрачные, нарезка — `scripts/extract-sprite-sheet.py`.

- Стратегия стен пересмотрена: вместо раскладки квадратных спрайтов по клеткам каменная лента идёт по контуру пола, углы скругляются, щелей и отдельных блоков нет. У залов появились ниши-альковы, чтобы убрать одинаковые прямоугольные коробки. Нарезка — `scripts/extract-wall-sheet.py`, рендер — `src/lib/wallPaint.ts`.

- Городской сценарий: нарезаны 40 рыночных спрайтов (шатры, прилавки, телеги, товары, столы, ограды), добавлены `marketStyle` (auto/rows/ring/fair) и `marketRichness`; площадь собирается вокруг колодца, входы остаются свободными, вокруг прокладывается кольцевая улица. ### P3 подземелья и P4 поселения (ноябрь 2026)

- **Подземелья** (`gen/dungeonArchitect.ts`, `DUNGEON_GENERATOR_VERSION = 1`):
  - назначения и формы залов, коридоры разной ширины, кольца, тайные комнаты;
  - 9 видов дверей (`doors.ts`) и связанные уровни;
  - уровень 0 использует seed проекта, остальные — `mix(seed, level, 0x1e7e1)`; лестницы считаются только из seed и размера.
- **Конвейер склепа для `plan.dungeon`:** `generateMap` пропускает для таких карт `normalizeTerrain` и `smoothTerrain`, чтобы не превратить купели в caveFloor. Монотонность детализации сохраняется, потому что обходные дорожки (`processionalLanes`) считаются только по клеткам.
- **Поселения** (`gen/settlementTypes.ts` — реестр, `gen/settlementPlanner.ts` — планировщик, `SETTLEMENT_GENERATOR_VERSION = 1`). Конвейер планировщика:
  1. география;
  2. центр и застроенная область;
  3. кольца стен (не выходят за карту);
  4. улицы по планировке: главные пробивают ворота и мосты;
  5. одна связная сеть;
  6. ворота и башни;
  7. площадь;
  8. кварталы по правилам и Вороного;
  9. причалы и сады;
  10. участки по меркам кварталов.
- **Конвейер `generateMap` для `plan.settlement`:** пропускается морфология и «дворы» у концов улиц. В `normalizeTerrain` вода такой карты считается спроектированной.
- **Рисование стен:** `townWallPaint.ts`. Террейн под стеной закрашивается травой.
- На тесных картах (меньше 36 клеток по меньшей стороне) улицы уже и второстепенных улиц не больше двух. Стены строятся только на картах от 24 клеток.

### Рынок: архетипы и планировщик (ноябрь 2026)

- **Реестр** `gen/marketArchetypes.ts` (`MARKET_GENERATOR_VERSION = 1`): 6 архетипов (village, city, port, caravan, bazaar, fair) и 18 специализаций. Архетип — данные: размеры, форма, покрытие, центр, входы, проходы, скелет, разрывы, неровность, зоны, специализации, структуры, декор, служебная сторона, карманы, `backfill` (запас за спиной места), совместимость и запасной архетип. `resolveMarketArchetype` разрешает 'auto' и ручной выбор с цепочкой замен.
- **Планировщик** `gen/marketLayout.ts` — чистый модуль без отрисовки. Шаги: место (`chooseMarketSite`/`resolveMarketSite`) → границы → входы от улиц → проходы → зоны → места → запас → декор → `validateMarket` → `MarketReport`. RNG — независимые потоки `stream(seed, ключи…)` на место и слот; `Math.random` не используется.
- **Интеграция**: классический `settlement.ts` и типизированный `settlementPlanner.ts` выбирают место рынка до улиц, красят проходы как `road`, площадь — `plaza` только для покрытия 'square'. Дома, чья дверь смотрит на площадь (в том числе через кольцевую улицу), получают вид из `frontage` архетипа. Порт ставит набережную, причал и груз (`marketWaterfront`).
- **Совместимость**: новый рынок включается только при `gen.marketArchetype` = 'auto' или id. Отсутствие поля или 'classic' — прежний рынок. `DEFAULT_GEN.marketArchetype = 'auto'`; `tests/golden.test.ts` фиксирует 'classic'. В типизированном планировщике хутор и крепость рынка не получают.
- **Тесты**: `tests/market.test.ts` (18): реестр, цепочки замен, guard поворота спрайтов, все архетипы × 4 размера × 2 насыщенности, стабильность скелета, детерминизм, различие композиций, порт и вода, ровное место, фасады, типизированные поселения, проект и JSON.

### Архитектурные комплексы подземелий (ноябрь 2026)
- Новая подсистема `src/lib/gen/complex/`, которая включается полем `gen.dungeonArchetype`. Без поля классический и разнообразный генераторы не меняются. Модули:
  - `registry` — архетипы, назначения, смежность;
  - `styles` — стили, состояния, материалы;
  - `graph` — 7 топологий;
  - `embed` — раскладка рамок;
  - `shapes` — 15 форм, составной зал;
  - `corridors` — A* с учётом поворотов, 8 типов;
  - `scenes` — сцены залов;
  - `index` — оркестратор, отчёт `ComplexReport`.
- 11 архетипов, 8 стилей, 8 состояний. Покрытие пола `map.floorLayer` рисует `src/lib/floorPaint.ts` в кэше земли. Природная порода получает скальную кромку стен в `wallPaint.ts`. Добавлен свет факелов, люстр и магических ламп; погашенные светильники помечены `unlit`.
- `repair.ts`: опорная клетка фигурного зала — ближайшая к центру проходимая клетка рамки. Для прямоугольных залов поведение прежнее, золотые тесты проходят.
- Правки уровней сохраняются при переходе (`src/lib/levelEdits.ts` и `App.onGen`) в памяти сеанса.
- Подробности, производительность и ограничения: `docs/dungeon/README.md`.

## 9. Что осталось

### Подземелья и поселения — что осталось после P3/P4
1. Уровни подземелья хранятся по одному. Правки уровня живут в памяти сеанса (`levelEdits.ts`), но в файл пишется только текущий уровень. Многоуровневый проект (массив карт) потребует схемы v2.
2. Комплексы: «обрушенное» состояние выражено слабо, в тюрьме и канализации обстановка редкая, водостоки плохо читаются на мелком масштабе. Подробности — в `docs/dungeon/README.md`, раздел 9.
3. `report.connected` у разнообразной планировки проверяет только середины залов. Полная проходимость проверяется в тестах BFS.
4. На малых картах (30×24) укреплённые типы вмещают 1–7 построек. Крепость на такой карте может остаться без цитадели.
5. Улицы — ленты по клеткам. Отдельных полигонов кварталов и именованных улиц нет.

### Рынок — что осталось
1. Классический портовый рынок на 60×44 (seed 1337) стоит в 2–3 клетках от воды за кольцевой улицей, а не прямо на набережной.
2. Ярмарка изредка убирает одно место без доступа (видно в заметках отчёта).
3. Спрайты шатров и прилавков мельче клетки 2×2, поэтому даже плотный базар выглядит воздушнее иллюстрированных карт. Фонарей, вывесок и флагов в наборе нет.
4. Середина большого городского рынка просторная — так задумано (свободная зона центра), но на 90×70 её можно уплотнить.

### P2.3 — качество
- Golden-фикстуры генерации (sha256 для наборов seed/размер/архетип).
- CI (typecheck + build + unit), `vitest`, `@playwright/test`, ESLint/Prettier.
- Перф-бюджеты для 100×80 и тест «detail монотонен».

### Другие треки (см. `docs/ANALYSIS-AND-PLAN.md`)
- **Данные:** `generatorVersion` для классических генераторов, квота localStorage, стабильные ID, схема v2, IndexedDB.
- **VTT (отложено пользователем):** `SceneBundle`, `.dd2vtt`, второй экран. Не начинать без явного запроса.
- **Рендер:** rAF + слои + чанковый кэш, DPR, баг «ландшафт меньше холста при cellSize > 48», производительность 100×80.
- **UX:** тач-жесты, a11y канвы, тосты/диалоги, дизайн-токены, i18n.
