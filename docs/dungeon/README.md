# Подземелья: архитектурные комплексы

Третий режим планировки подземелья, рядом с «Классической» и «Разнообразной» (P3).
Включается полем `gen.dungeonArchetype`. Без этого поля прежние генераторы работают
байт в байт как раньше: золотые тесты закреплены на `classic`, а тесты `varied` не менялись.

## 1. Аудит (до изменений)

Карта зависимостей генерации подземелья:

```
generateMap (generator.ts)
 └─ generateDungeon
     ├─ classic: прямоугольные залы → decorateCrypt (cryptLayout.ts)
     └─ varied:  generateVariedDungeon (gen/dungeonArchitect.ts)
          ├─ граф MST + кольца, 14 ролей, 9 форм, A*-коридоры, 8 видов дверей
          ├─ levelLinks / stairFootprint — лестницы 6×6 на одних клетках соседних уровней
          ├─ furnishByPurpose / cryptCompositionPlan / placeCorridorTraps (gen/cryptplan.ts)
          └─ decorateCrypt → repairMap (gen/repair.ts)
render.ts: paintGround (groundCache) → drawWalls (wallPaint.ts) → cryptPainter (cryptPaint.ts)
project.ts: проверка формата; App.tsx: история правок, автосохранение
```

Ограничения, ради которых появилась подсистема:

- у всех архетипов одна топология (MST + кольца);
- нет составных залов, а коридор по всей длине одной ширины;
- нет архетипов крепость, шахта, канализация, лаборатория и руины;
- нет систем стиля, состояния и материалов пола;
- свет есть только у жаровен, алтарей, рунных кругов и свечей;
- нет гибрида с пещерой;
- один генератор случайных чисел на всё.

Решение: построить новую подсистему `src/lib/gen/complex/` поверх существующих модулей,
а не переписывать `dungeonArchitect`. Подсистема переиспользует:

- `levelLinks` и `stairFootprint` — связи уровней;
- `decorateCrypt`, `furnishByPurpose`, `cryptCompositionPlan`, `placeCorridorTraps` — обстановку;
- `repairMap`, каталог `CRYPT`, `canPlaceCrypt`, `cryptWalkable` — проверки и предметы.

## 2. Конвейер

```
complexProfile  → архетип, топология, геометрия, стиль, состояние, роль яруса, доля природы
buildGraph      → граф узлов: вход, главный зал, узлы, галереи, служебные, тайные, природные, финал, спуск
embedGraph      → рамки залов по опорным точкам топологии и по связям; главный зал — не у края
roomGeometry    → маска зала: форма, колонны, ниши, купель, вода, части составного зала
routeCorridor   → A* с учётом поворотов; carveCorridor — ширина вдоль пути, колоннада, водосток, природный хвост
двери           → вид по роли ребра и назначению зала (ворота, решётка, арка, пролом, тайная)
состояние       → проломы стен к пещерам, затопление низин, износ пола, обломки, корни, мох
материалы       → floorLayer: материал по стилю и категории зала, бордюры, центральные орнаменты
сцены           → SCENES: главный объект, второстепенные, декор и свободное место; 1–3 варианта на назначение
свет, механизмы → настенные факелы, люстры, магические лампы, кристаллы, грибы; погашенные — unlit
freePockets     → локальная починка: убирает предмет, который отрезал карман пола
проверка        → BFS от входа, отчёт ComplexReport в map.plan.dungeon.complex
```

**Потоки случайных чисел.** Каждый этап получает свой поток `mulberry32(mix(levelSeed, salt))`:

| поток | соль |
|---|---|
| структура | `0x5712` |
| раскладка | `0x9e0` |
| коридоры | `0xc0f` |
| декор | `0xdec` |
| свет | `0x119` |
| разрушения | `0x2a1` |

Поэтому, например, смена числа светильников не сдвигает геометрию.
`Math.random` не используется; тест подменяет его функцией, которая бросает исключение.

**Если на тесной карте зал не удалось связать** даже запасным ходом к ближайшему связанному залу,
весь уровень строится заново на один узел меньше. Это детерминированно, а отчёт показывает,
сколько залов не поместилось.

## 3. Архетипы

У каждого архетипа свои:

- веса топологий;
- пул назначений;
- типы и ширина коридоров;
- двери;
- вода;
- стиль и состояния по умолчанию;
- механизмы.

Реестр: `complex/registry.ts`.

| Архетип | Топологии | Стиль | Характер |
|---|---|---|---|
| fortress — крепость | multihub, central, ring | дварфийский | казармы и оружейная рядом с караулом, ворота и решётки, галереи |
| mine — шахта | maze, branching, linear | индустриальный | выработки, тоннели, подъёмники; нижний ярус — пещеры |
| temple — храм | linear, central, ring | религиозный | ось к святилищу, колоннады, часовни, водоём |
| sewer — канализация | ring, maze, multihub | средневековый | водостоки с дорожками, коллекторы, цистерны, решётки стока |
| laboratory — лаборатория | branching, multihub, central | эльфийский | лаборатории, библиотека рядом с архивом, хранилища, ритуальная |
| ruins — руины | maze, mixed, branching | древний | организованная неполнота, проломы, природа в кладке |
| catacombs — катакомбы | ring, maze | некромантический | погребальные ниши, костницы, много колец |
| tomb — гробница | linear, branching | древний | парадная ось, ловушечный коридор, сокровищница за механизмом |
| prison — тюрьма | central, branching | средневековый | караульный центр, блоки камер, допросная |
| cavern — пещера | branching, maze, mixed | примитивный | без кладки и дверей, озеро, минералы |
| hybrid — гибрид | multihub, mixed | дварфийский | каменные залы в пещерах: проломы, тоннели, кладка у озера |

**Правила смежности** (`AFFINITY`): казармы ↔ караул, оружейная ↔ караул и казармы,
кухня ↔ склад, архив ↔ библиотека, камеры ↔ караул, костница ↔ погребальный зал. Сокровищница и тайник — защищённые тупики.

Стилей 8: дварфийский, эльфийский, древний, средневековый, некромантический, религиозный,
индустриальный и примитивный. Стиль един для всех ярусов комплекса.

Состояний 8: сохранённое, заброшенное, повреждённое, разрушенное, обрушенное,
частично затопленное, захваченное природой и вновь заселённое. Глубокие ярусы по умолчанию запущеннее.

## 4. Формы и коридоры

**Формы залов:** прямоугольник, квадрат, круг, овал, восьми- и шестиугольник, Г, Т, крест,
зал с нишами, с перегородками, неправильная, галерея, составной (неф + крылья + апсида),
пещера. Маска связна (`keepConnected`); колонны, купель и вода лежат только на маске.

**Коридоры:** прямой, с изломом, извилистый, галерея, колоннада, узкий тоннель, природный тоннель
и водосток. Ширина берётся из диапазона архетипа и меняется вдоль пути: у природного хвоста коридор
расширяется. Ось коридора остаётся сухой и свободной от колонн.

## 5. Уровни

Связи переиспользуют `levelLinks`, поэтому лестницы, винтовые лестницы, подъёмники и обвалы стоят
на одних клетках соседних уровней. Клетки связи и путь к центру зала-спуска всегда остаются полом:
их не затапливает и не заставляет мебель (до исправления 14 из 22 проверок давали рассогласование).

Роль яруса: верхний, средний, глубокий или пещерный (нижний ярус шахты, руин и гибрида).

Правки уровня хранятся в памяти сеанса (`src/lib/levelEdits.ts`) и возвращаются при переходе на этот
уровень, пока не изменены другие настройки генерации. Формат проекта не меняется: в файл пишется
текущий уровень.

## 6. Формат проекта

Версия формата остаётся 1, все поля необязательные.

- `gen.dungeonArchetype` — id из `COMPLEX_ARCHETYPE_IDS`.
- `gen.dungeonTopology`, `gen.dungeonGeometry`, `gen.dungeonStyle`, `gen.dungeonCondition` — `'auto'` или id.
- `map.floorLayer` — `{ codes, ornaments }`:
  - `codes` — строка длиной W·H из алфавита `FLOOR_CODE_PATTERN`: строчные буквы — поле зала, заглавные — бордюр, `n` — природная порода, `.` — без покрытия;
  - `ornaments` — массив `{ x, y, r, kind }`.
- `CryptObject.unlit` — погашенный светильник.

## 7. Проверки и производительность

`tests/complex.test.ts` — 26 тестов:

- граф всех архетипов и топологий;
- связные маски форм;
- 8 контрольных архетипов × 3 seed: связность, отрезанный пол ≤ 5 %, предметы на допустимых клетках, двери не заставлены, нет вырубок `repairMap`;
- различимость архетипов и композиций;
- уровни: совпадение клеток и видов связей, единый стиль;
- детерминизм без `Math.random`;
- круговой проход через JSON, отклонение битых данных, совместимость старых проектов и прежних генераторов;
- правки уровней, ползунки и переключатель ловушек;
- следы состояний «обрушенное» и «вновь заселённое».

Время генерации, Node 20, 11 архетипов × 3 seed:

| Карта | медиана | p90 | максимум |
|---|---|---|---|
| 44×30, 8 залов | 34 мс | 67 мс | 102 мс |
| 64×46, 11 залов | 67 мс | 107 мс | 166 мс |
| 100×80, 14 залов | 149 мс | 198 мс | 231 мс |

Для сравнения: «Разнообразная» планировка на 44×30 занимает 43 мс.

Отрисовка в headless Chromium на программном рендере: 340–640 мс при 20–24 px на клетку.
Покрытие пола живёт в кэше «земли» и при перемещении предметов не перерисовывается.

## 9. Ограничения

- Обстановка залов местами редкая: тюрьма, канализация.
- «Обрушенное» состояние выражено слабо: обломки и осыпи без перекрытых завалами ходов.
- Водостоки канализации на мелком масштабе читаются плохо.
- Отдельных спрайтов для стилей нет: стиль меняет материалы пола, двери, подстановки сцен и свет, но не рисунок стен.
- Правки уровней живут только в памяти сеанса; в файл пишется текущий уровень.
- Ловушки и механизмы только визуальные, по требованию задачи.
